# RF Spectrum Explorer

This repository contains a FastAPI backend and a Next.js frontend used to explore RF spectrum artifacts generated by rfproc. The backend reads gold holds data from MinIO, while the frontend renders summary traces and band metadata.

## Repository Layout

```
backend/        FastAPI application
frontend/       Next.js application
```

## Backend

The FastAPI backend exposes the following endpoints:

- `GET /bands/surveys` – list available surveys from run manifests
- `GET /bands/survey/{survey_id}/bands` – list bands for a survey
- `GET /bands/survey/{survey_id}/band/{band_id}/holds?max_points=<n>` – get normalized holds data (min/max/avg) for a band
- `GET /api/assignments/overlay?site={site}&band_start_hz={start}&band_stop_hz={stop}&valid_on={date}` – get assignment overlays for a frequency band
  - Query parameters: `site` (required), `band_start_hz` (required, Hz as integer), `band_stop_hz` (required, Hz as integer), `valid_on` (optional, YYYY-MM-DD)
  - Returns: JSON array of assignment overlay records

Survey ID format: `{mission_type}:{site}:{sensor}:{run_id}` (e.g., `survey:Lask:CRFS:run01`)

The backend reads data from MinIO using run manifests as a discovery index. Gold parquet files are read lazily when a specific band is requested.

### MinIO Configuration

Environment variables (backend):
- `MINIO_ENDPOINT` (e.g., `10.10.100.28:9000`)
- `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`
- `MINIO_BUCKET` (default `rf-lake`)
- `MINIO_USE_SSL` (`true`/`false`)
- Optional `MINIO_REGION`

### PostgreSQL Configuration (for Assignment Overlays)

Environment variables (backend):
- `PGHOST` (e.g., `surveyviewer-postgres` or IP address)
- `PGPORT` (default `5432`)
- `PGDATABASE` (database name)
- `PGUSER` (database user)
- `PGPASSWORD` (database password)

Note: The database schema must be applied manually on rf-lakehouse using the migration file at `db/migrations/001_create_assignments.sql`.

## Frontend

The Next.js app provides:

- `/` – home page with link to surveys
- `/surveys` – list available surveys and bands
- `/survey-band/[survey_id]/[band_id]` – interactive explorer with Plotly traces showing min/max/avg holds

Key features:
- Survey/band listing from rfproc run manifests
- Interactive Plotly.js line traces (min, max, avg curves)
- Metadata display (frequency range, trace count, mission info)

API utilities are provided in `frontend/lib/api.ts` to communicate with the backend.

## Running with Docker Compose

1. Set MinIO environment variables (see backend configuration above)
2. Build and start the services:

   ```bash
   docker-compose up --build
   ```

3. Access the frontend at http://localhost:3000 and the backend docs at http://localhost:8000/docs.

## Local Development

### Backend

Create a virtual environment and install dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
```

Run the API locally:

```bash
uvicorn app.main:app --app-dir backend/app --reload
```

Set MinIO environment variables (see configuration above).

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Set `NEXT_PUBLIC_API_BASE` to point at the backend (defaults to `http://localhost:8000`).

## Data Source

The viewer reads gold holds data from rfproc-generated parquet files stored in MinIO:

- Path format: `gold/mission_type={mission_type}/site={site}/sensor={sensor}/run_id={run_id}/band_id={band_id}/product=holds/data.parquet`
- Discovery: Uses run manifests at `runs/mission_type={mission_type}/site={site}/sensor={sensor}/run_id={run_id}/run_manifest.json`
- Only run manifests with `status="success"` are included

The `/bands/survey/{survey_id}/band/{band_id}/holds` endpoint supports an optional `max_points` query parameter (recommended: 50000) to downsample large arrays for better performance.
